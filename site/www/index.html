A map of how you build with coding agents

Git records what changed. Cartographer records how you got there.

It reads the session history your coding agent already keeps and tells it back to you as a story: what you did, what happened, what it meant, how you responded. When a version is done, it appraises the whole build against the outcome you said you wanted. Evidence on every line, no flattery.

Install in one lineWatch a real build replay

Works with Claude Code today. Runs on your machine only. Plain Python, no dependencies, MIT.

Install

One line in a terminal. It downloads Cartographer into a folder in your home directory and adds four commands to Claude Code. Nothing runs in the background unless you ask for it.

Mac and Linux (Terminal):

curl -fsSL https://codecartographer.dev/install.sh | sh

Windows (PowerShell):

irm https://codecartographer.dev/install.ps1 | iex
Plain language

If you don't live in a terminal

  1. Open a terminal. Mac: press ⌘ Space, type Terminal, Enter. Windows: press the Windows key, type PowerShell, Enter. A window with a blinking cursor appears.
  2. Paste the line for your system and press Enter. It prints what it is doing. Thirty seconds, no questions. If it says Python is missing: on a Mac run xcode-select --install; on Windows run winget install Python.Python.3.12; then open a new terminal and paste the line again.
  3. Open your dashboard. Type cartographer serve --open and press Enter. A page opens in your browser. Only your computer can see it.
  4. Answer six questions. How comfortable you are with code, how experienced with prompting, what the map should sound like. This decides how Cartographer speaks to you. You can change it any time.
  5. Work in Claude Code as usual. Cartographer does nothing during the session.
  6. At the end of a session, type /wrap. Claude writes the map and tells you where the replay is. Come back to the dashboard, or type cartographer open, to watch it.
Technical

What the script does, exactly

  1. Checks for python3 3.9+. Nothing else is required. No pip, no venv, no npm.
  2. Downloads cartographer.tar.gz from this site (built from main on every deploy), falling back to git clone.
  3. Runs bin/cartographer install --agent claude-code. That copies the checkout to ~/.cartographer/app, symlinks ~/.local/bin/cartographer, and copies the skills to ~/.claude/skills/ (wrap, replay, complete, cartographer-setup).
  4. Touches ~/.claude/settings.json only with --auto, adding a SessionEnd hook that maps each session when it ends. Default is manual.
  5. Tells you if ~/.local/bin is not on your PATH, with the line to add.
  6. Windows: install.ps1 does the same with py or python, unpacks cartographer.zip, writes cartographer.cmd (PowerShell, cmd) and a shim for Git Bash (which Claude Code uses) into ~\.local\bin, and adds that folder to your user PATH. Hooks are registered as "python.exe" "…/bin/cartographer" hook claude-code, so they run without a Unix shell.

Manual install

git clone https://github.com/situatedstrategies/cartographer && cd cartographer ./bin/cartographer install --agent claude-code # add --all for Codex CLI and Cursor, --auto for hooks cartographer config init # or: cartographer serve --open cartographer doctor # what is installed, where, and what it found

Uninstall

rm -rf ~/.cartographer ~/.local/bin/cartographer ~/.claude/skills/{wrap,replay,complete,cartographer-setup} # Windows (PowerShell): Remove-Item -Recurse ~\.cartographer, ~\.local\bin\cartographer*, ~\.claude\skills\wrap, ~\.claude\skills\replay, ~\.claude\skills\complete, ~\.claude\skills\cartographer-setup # and, if you used --auto, remove the cartographer SessionEnd hook from ~/.claude/settings.json

Everything lives under ~/.cartographer (or $CARTOGRAPHER_HOME): config, one JSON map per session, appraisals, rendered replays. Raw transcripts are never copied there. Secrets are redacted before anything is written.

In Claude Code

Four commands. Each one runs the CLI, hands Claude a brief, and lets Claude do the reading. The map is written by the agent that was in the room, which is why it knows what you meant.

/wrap

At the end of a session. Cartographer digests the transcript into a timeline with a reading of every prompt, writes a brief tuned to your profile and the languages you used, and Claude writes the map: chapters, then moves (what you did, what happened, what it meant, how you responded), each citing its evidence. Then it files the map under the git repo you were in and renders the replay.

/wrap myproject names the project · /wrap --session <id> maps an older session · --force redoes one

/replay

The story of every wrapped session of a project, across branches, told one move at a time, with the playbook underneath: coaching, prompts worth reusing, how you build, where time went. /replay myproject, or just /replay to pick.

/complete

When a version is done. Claude asks what "done" meant, in your words, if you never declared it, then the result (shipped, partial, abandoned) and what actually happened. Then it writes the appraisal: what got you there, what cost you and how many minutes, what was carried into the result and what it will cost later, how you prompted and what it did. Every item cites session and move ids; praise words are rejected.

/cartographer-setup

Change your profile in conversation, switch manual and automatic wrapping, or backfill maps of old sessions. /cartographer-setup backfill lists past sessions and maps the ones you pick.

What a session looks like

  1. Before you start (optional, recommended): cartographer goal "what done means for this version" in the repo. This is the yardstick every map is judged against.
  2. Build as usual. Prompts, corrections, dead ends, fixes. Cartographer is not running.
  3. /wrap at the end. Claude reads the brief, writes the map, saves it, and gives you the trailer: one line on what happened, three to five beats, one observation about how you build, coaching if you turned it on, and the replay path.
  4. Repeat across sessions. Each one lands in the same project; the replay stitches them into one story.
  5. /complete when the version ships. The honest reading of the whole build against what you wanted.

Codex CLI and Cursor: install with --all and say "wrap up this session with cartographer". Their adapters follow the documented formats but have not yet been verified on real history; expect rough edges.

Commands

The same engine from a shell. You rarely need these if you use the Claude Code commands and the dashboard, but they are all there.

CommandWhat it does
cartographer serve --openThe dashboard in your browser, this machine only: profile, recent sessions with a Map this session button, projects, maps, outcomes and completion.
cartographer open [project]Open a replay directly. Newest project if you name none.
cartographer sessions --allEvery session found for every installed agent. ✓ means already mapped.
cartographer wrap [--session id] [--force] [--run]Write the brief for a session. --run also maps it with the agent's headless CLI, no human in the loop.
cartographer goal "…"Declare what done means for the current version of the repo you are in. The source of truth for every map and the appraisal.
cartographer complete --result shipped|partial|abandoned --actual "…"Close the version and write the appraisal brief. --run appraises headlessly.
cartographer save file.json [--check]Validate, redact, file and render a map or an appraisal. --check only validates. This is what Claude runs at the end of /wrap.
cartographer projectsEvery project with its sessions, versions, declared outcomes and appraisals.
cartographer render --project name [--open]Rebuild a replay page. Also takes map and appraisal files directly.
cartographer backfill --cwd repo [--run]Briefs (or, with --run, maps) for every past session of a repo. Retrospective maps.
cartographer sweep [--dry]Map every session that has gone quiet and isn't mapped yet. For agents with no session-end event; run it on a schedule.
cartographer config show | set key value | initYour profile and settings, in the terminal. init is the wizard.
cartographer install --agent claude-code|codex|cursor|all [--auto]What the installer runs. Rerun after updating.
cartographer doctorVersion, home folder, mode, which agents were found and how many sessions, headless runners.

How it works

Reads what already exists

Claude Code keeps one file per session. An adapter turns it into a plain stream of events: prompts, replies, tools, errors, branch changes. No capture, no plugin in the loop, no cloud.

Reads every prompt

What act it performs (build, fix, repair, accept, ask), what it anchors to (files, symbols, errors, pasted code), how it is said (imperative, question, hedged, delegated). A turn that starts with "no, I meant…" marks the previous move as having gone wrong for you, even if the code ran.

Hands the agent a brief

Facts, your profile, what Cartographer knows about the languages you used, the reading of each prompt, the rules, the timeline. The agent that was in the session writes the map. Any agent can follow the same brief.

Judges against a yardstick

Session maps are provisional. The outcome you wanted is only known when a version is done, so /complete is where the verdict lives. Every move and every appraisal item must cite its evidence in the record; praise words are rejected on save.

Questions

Does anything leave my machine?

No. Maps, config and replays live in ~/.cartographer. The dashboard binds to 127.0.0.1 and refuses requests from anywhere else. The only network call is the installer downloading Cartographer. Team sharing, when it comes, will be a choice you make, not a default.

Is there a Mac installer (.pkg)?

Not yet. A signed and notarised package is on the list. The one-line installer does the same thing on Mac and Linux without needing Apple's signing, and it is what we test.

Windows?

Yes, natively: the PowerShell line above. It needs Python 3.9+ (winget install Python.Python.3.12) and Claude Code, which brings Git Bash with it. The Windows path is new and has had less real-world use than Mac and Linux; if anything breaks, support@codecartographer.dev with the output of the installer is enough to fix it. WSL works as well.

Can I map sessions from before I installed it?

Yes. /cartographer-setup backfill or cartographer backfill --cwd <repo> prepares a brief for every past session Claude Code still has on disk.

What does "honest" mean here, mechanically?

Three enforced rules. Every move lists the timeline items it rests on. "What it meant" has to name the technical implication, not an adjective. Saving rejects praise words in the map and the appraisal. And the verdict waits for completion, because a session cannot judge itself.

How do I update?

Run the install line again. It replaces ~/.cartographer/app and the skills; your maps and config stay.
