# codecartographer.dev

Everything for the domain that is not the CLI itself.

| Folder | What |
|---|---|
| `www/` | The public site, one page per topic (`index`, `install`, `claude-code`, `commands`, `how-it-works`, `questions`) sharing `site.css`; `install.sh` and `install.ps1` (the one-line installers); `_headers` (content types). `demo.html`, `cartographer.tar.gz` and `cartographer.zip` are generated by `build.sh`, not committed. |
| `build.sh` | Copies the demo replay in and packs the checkout as the tarball and zip the installers download. |
| `wrangler.toml` | The site as an assets-only Worker, for the Workers way of deploying below. |
| `email-worker/` | Cloudflare Email Worker that tags mail for support@ and mapit@ and forwards it. Its own README has the routing steps. |

## Deploy the site (Cloudflare)

Cloudflare offers two ways to host static files from a repository. Both work; the settings differ, and the three or four fields must come from the same row. Cloudflare runs the build command **inside the root directory**, which is why `sh site/build.sh` fails when the root directory is `site`.

**Workers** (what "Create → Workers → Import a repository" makes; the check on pull requests is called "Workers Builds"). `site/wrangler.toml` tells it that the Worker only serves the files in `www/`; its `name` must match the Worker's name in the dashboard (`cartographer`). Pages are served at clean URLs (`/install` is `install.html`); the demo replay opens in a new tab.

| Root directory | Build command | Deploy command |
|---|---|---|
| `site` | `sh build.sh` | `npx wrangler deploy` |

**Pages** ("Create → Pages → Connect to Git"), no wrangler config involved:

| Root directory (advanced) | Build command | Build output directory |
|---|---|---|
| *(empty, the repository root)* | `sh site/build.sh` | `site/www` |
| `site` | `sh build.sh` | `www` |

Either way: production branch `main`, framework preset None, no environment variables. Then add `codecartographer.dev` under Custom domains (Cloudflare adds the DNS record), and check that `https://codecartographer.dev/install.sh` and `/cartographer.tar.gz` both download before trying the one-liner on a clean machine. `www/_headers` makes the two installers come back as plain text, so piping them into a shell works.

Every push to `main` rebuilds the site and both download bundles, so the installer always ships the current `main`.

## Preview locally

```bash
sh site/build.sh && python3 -m http.server -d site/www 8080
```

Then open http://localhost:8080/. To test the installer against the local build without touching your real setup:

```bash
HOME=$(mktemp -d) CARTOGRAPHER_TARBALL=site/www/cartographer.tar.gz sh site/www/install.sh
```
